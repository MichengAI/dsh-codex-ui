# 开发与构建

更新时间：2026-08-27（Asia/Shanghai）

要求 Node.js 22+，项目固定 pnpm `11.22.0`。

## 常用命令

```powershell
pnpm install --frozen-lockfile
pnpm test
pnpm build
```

`pnpm test` 顺序执行：

1. `tsc --noEmit` 严格类型检查；
2. `vitest run` 执行 `tests/**/*.spec.ts` 的 jsdom 行为/集成测试；
3. `tsdown` 构建 Host 与 Client 产物；
4. `node tests/run-assertions.mjs` 执行遗留源码契约与纯函数断言。

产物：

- `dist/index.mjs` / `dist/index.d.mts`：Host 入口与类型。
- `dist/client.js`：由 DSH ModuleLoader 加载的 Client bundle。

## 门禁

- `.github/workflows/ci.yml` 在 main push 与所有 PR 上以 Node.js 22、24 运行完整测试。
- `.github/workflows/release.yml` 在 `v*` tag 上先跑完整测试，再生成双语说明和创建 GitHub Release。
- `.github/workflows/publish.yml` 在 `v*` tag 上以 npm Trusted Publishing（OIDC）运行完整测试、校验标签与 `package.json` 版本一致后发布到官方 npm registry。首次启用前，需在 npm 包设置中绑定 `MichengAI/dsh-codex-ui`、工作流文件 `publish.yml`，并仅允许 `npm publish`。
- 提交前至少执行 `pnpm test` 与 `git diff --check`；Windows 的 LF/CRLF 提示本身不等于失败。
