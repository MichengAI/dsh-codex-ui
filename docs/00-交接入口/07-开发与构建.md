# 开发与构建

更新时间：2026-09-09 18:53（Asia/Shanghai）

要求 Node.js 22+，项目固定 pnpm `11.22.0`。

## 常用命令

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm test
pnpm build
```

`pnpm test` 顺序执行：

1. `tsc --noEmit` 严格类型检查；
2. `vitest run` 执行 `tests/**/*.spec.ts` 的 jsdom 行为/集成测试；
3. `tsdown` 构建 Host 与 Client 产物；
4. `node tests/run-assertions.mjs` 执行源码契约、宿主认证、workflow YAML 结构与隔离的双语发布全链路断言；
5. `pnpm run test:layout` 使用 Chromium 执行真实 CSS 几何、颜色与空状态检查，不生成截图。首次运行需安装浏览器；Linux CI 使用 `pnpm exec playwright install --with-deps chromium`。

产物：

- `lib/index.mjs` / `lib/index.d.mts`：Host 入口与类型。
- `lib/client.js`：由 DSH ModuleLoader 加载的 Client bundle。

## 门禁

- `.github/workflows/ci.yml` 在 main push 与所有 PR 上以 Node.js 22、24 运行完整测试。
- `.github/workflows/release.yml` 在 `v*` tag 上先跑完整测试，再生成双语说明和创建 GitHub Release。
- `.github/workflows/publish.yml` 在 `v*` tag 上以 npm Trusted Publishing（OIDC）运行完整测试、校验标签与 `package.json` 版本一致后发布到官方 npm registry；根包发布成功后会自动调用 Suite Installer 发布流程。首次启用前，需在 npm 包设置中绑定 `MichengAI/dsh-codex-ui`、工作流文件 `publish.yml`，并仅允许 `npm publish`。
- `.github/workflows/release-suite-installer.yml` 可手动触发，也可由根包发布成功后自动调用：它读取九个成员（含 BTW、Simplify、Codex Pet）的官方 npm `latest`，写入 Installer 的精确版本清单，并仅同步兼容聚合包已有的历史成员及锁定文件，不扩大旧包声明权。运行完整测试后通过 OIDC 发布 Installer，并创建 `suite-installer-v*` 标签和 GitHub Release；安装时使用发布时锁定的版本。Installer 要求 Node.js `22.19.0+`。首次启用前，需为 `@michengai/dsh-codex-suite-installer` 单独绑定同仓库的该工作流，并仅允许 `npm publish`。
- 提交前至少执行 `pnpm test` 与 `git diff --check`；Windows 的 LF/CRLF 提示本身不等于失败。
