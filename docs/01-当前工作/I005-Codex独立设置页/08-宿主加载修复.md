# 独立设置页宿主加载修复

更新时间：2026-09-08 21:12（Asia/Shanghai）

## 问题与证据

用户重启后仍看到旧设置弹窗。旧包的全局弹窗尺寸删除已生效，因此文件安装成功不代表新组件被选中。

官方 `ui-settings-general` 声明 `settings.trigger` 等子插槽；新壳虽然注册了更低 priority，但再次声明同名 children。真实 `SlotCore` 禁止重复声明，不允许使用 shadowing 转移子插槽声明权。新增测试执行官方发布包的 `apply` 后复现 `slot "settings.trigger" is already declared`。首轮示例预览没有经过真实装配，因此遗漏该问题。

## 修复

- `cordis.patch.yml` 停用 `ui-settings-general`，与侧栏接管方式一致。
- 新设置壳唯一声明设置树，普通偏好和第三方 section 继续由原插件提供。
- Host 调用官方公开的 schema 注册函数，保留 `ui-onboarding` 持久化协议。
- 配置文件按钮通过 `settingsScope.describe()` 判断可用性，通过 `remote.settings.openSettingsDocument()` 打开，保留 loopback 限制、防重入及失败提示。
- 客户端依赖声明改为设置基础服务及连接服务，避免依赖被停用的壳。
