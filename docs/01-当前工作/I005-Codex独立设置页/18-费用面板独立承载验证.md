# 费用面板独立承载验证

更新时间：2026-09-09 00:23（Asia/Shanghai）

状态：实验通过，未接入正式设置、真实账单或用户安装。未提交、推送、发布。

## 结论

费用插件 1.0.42 的完整原面板可以在专用 iframe 承载页内运行，无需修改社区插件文件或重写统计 UI。之前将“缺少独立 HTML 页面”理解为必须修改插件的结论不成立；缺少的环境可以由独立承载页提供。

## 实现范围

- `scripts/preview-billing.mjs`：loopback 预览服务，主页面嵌入 `/billing-frame`。从已安装包读取原始 client.js 并原样提供，不把副本纳入仓库；默认读取用户 Web profile，可通过 DCU_BILLING_PACKAGE 指定包目录。
- `scripts/billing-frame-preview.tsx`：在 iframe 内建立 React、原版 Modal/Menu/Tooltip 和 store 环境。原插件 apply 的装配适配仅接入词典及 sidebar.footer.action，从其声明取得组件、预算状态和注入参数；不启动第二个 DSH、不注册会话通知。
- 原 Modal 继续挂到 iframe 自己的 document.body，保留原有焦点管理。样式仅在承载页内让弹窗填满 iframe，隐藏外层遮罩及重复标题，保留原关闭按钮。
- 父子页面消息核对同源与 source，负责主题同步和关闭；关闭时卸载 iframe 页面，重新打开重新装载。
- 所有账单 API 使用明确标示的空数据夹具，不读取用户真实费用、会话、凭据或余额，不代理运行中的 DSH。POST 等写请求返回 405；预算等本地状态仅存于隔离预览 origin。
- iframe 自己的模型健康检查返回未检查，不把未连接的模型显示为故障。承载页安全策略限制连接至预览自身。

## 复查

```powershell
$env:DCU_BILLING_PREVIEW_PORT = '4319'
node scripts\preview-billing.mjs
# 另一终端执行
node scripts\verify-billing-frame.mjs
```

浏览器地址：[承载验证页](http://127.0.0.1:4319/)。预览服务仅在运行期间有效。

检查已通过：iframe 内独立挂载、概览/账单/用量/趋势/费率/设置六个分区、币种切换、深浅主题同步、关闭重开及 Escape；1400×960 与 1100×760 外层无横向溢出，未捕获页面异常。[实验截图](17-费用iframe承载实验.png)。未验证真实账单筛选结果、配置写入或所有内部弹层。
